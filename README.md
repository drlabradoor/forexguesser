# Forex Signal Mini App

Telegram Mini App: пользователь загружает скриншот графика, Claude Sonnet 5 распознаёт инструмент и таймфрейм и
выдаёт торговый сигнал — направление, вход, стоп-лосс, три тейк-профита, список ключевых признаков и текстовый
разбор. Один бесплатный разбор на пользователя показывается закрытым: видно только распознанные инструмент и
таймфрейм, сам сигнал открывается вместе с доступом. Дальше — переход по диплинку в личку с уже подставленным
сообщением.

Интерфейс — три таба: «Скриншот» (профиль, загрузка и результат), «Сигналы» (история разборов, у пользователя без
доступа — строками с закрытым содержимым) и «Торговля» — пока заглушка «Доступно в полной версии».

Доступ выдаётся вручную из админ-панели (флаг «Безлимит»). Без него сервер отдаёт клиенту только распознанные
инструмент и таймфрейм: направление, уровни, признаки и разбор не покидают бэкенд.

Пока идёт разбор, по загруженному скриншоту ходит подсвечивающий его луч, в углу растут проценты, а поверх
картинки меняются четыре фазы. Прогресс фейковый — запрос к модели один, промежуточных этапов у него нет, — но
на 100% счётчик не встаёт, пока ответ действительно не пришёл, и зависнуть на «100%, и ничего» он не может.
Минимальная длительность — 2.5 секунды: анимацию снимают на видео, и на быстром ответе её иначе не разглядеть.

Фронтенд — ванильные ES-модули в `public/js/` без сборки: `app.js` (роутер табов), `api.js`, `state.js`, `screens/`.
Бандлера нет намеренно — по той же причине, по которой нет шага сборки на бэкенде (см. «Продакшн» ниже).

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `ANTHROPIC_API_KEY` | да | Ключ Anthropic API |
| `OWNER_TELEGRAM_ID` | да | Ваш numeric Telegram ID (владелец, может назначать админов) |
| `DATABASE_URL` | да | Строка подключения PostgreSQL. TLS задаётся в самом URL: `?sslmode=require` для баз, которые его требуют; без параметра соединение идёт без шифрования |
| `TARGET_USERNAME` | да | Username для диплинка (с `@` или без) |
| `APP_URL` | да | Публичный HTTPS-URL приложения |
| `PORT` | нет | По умолчанию `3000` |
| `SKIP_BOT_POLLING` | нет | `true` — не запускать поллинг бота |

## Настройка (один раз)

1. Создать бота через @BotFather, сохранить токен в `BOT_TOKEN`.
2. Задеплоить приложение на HTTPS-хостинг, записать выданный URL в `APP_URL`.
3. Написать боту `/id` — он ответит вашим Telegram ID. Записать его в `OWNER_TELEGRAM_ID` и передеплоить.
4. Заполнить `TARGET_USERNAME`, `DATABASE_URL` и `ANTHROPIC_API_KEY`.

Схема БД создаётся автоматически при старте (`CREATE TABLE IF NOT EXISTS`) — миграции запускать не нужно.

## Демо-режим (съёмка промо)

В админке рядом с «Безлимитом» есть флаг «Демо». Он нужен, когда приложение показывают на камеру, и включает всё
сразу одним тумблером:

- в шапке вместо настоящего имени — «Трейдер», аватар и Telegram ID не выводятся. Подмена делается на сервере:
  скрытое стилями всё равно уехало бы в разметку, а снимают именно этот экран;
- доступ к сигналам выдаётся без отдельного «Безлимита»;
- лимит бесплатного прогона снимается, поэтому дубли снимаются подряд без сброса через админку;
- модель просят отвечать короче (`rationale` в 1-2 предложения, ровно 3 «ключевых признака») — выходные токены
  генерируются последовательно и составляют основную часть задержки.

Последний пункт означает, что **ролик показывает скорость, которой у обычного пользователя не будет**: платящий
получает развёрнутый разбор, за него и платят. Это осознанный компромисс, а не недосмотр.

## Команды бота

- `/start` — кнопка запуска анализатора
- `/id` — узнать свой Telegram ID
- `/admin` — кнопка админ-панели (только для админов)

## Разработка

```bash
npm install
npm run dev
```

Для проверки внутри Telegram нужен публичный HTTPS-туннель (например `cloudflared tunnel --url
http://localhost:3000`) — Telegram не открывает `http://` или `localhost` как Mini App. URL туннеля указать в
`APP_URL`.

## Тесты и типы

```bash
npm test            # vitest, использует pg-mem — реальная БД не нужна
npm run typecheck   # tsc --noEmit (покрывает только src/)
npm run test:e2e    # playwright: сквозной прогон воронки
```

### Сквозной тест

`npm run test:e2e` поднимает **настоящее приложение** (`buildApp`) поверх in-memory Postgres — подделан только
Claude — отдаёт настоящий фронтенд из `public/` и прогоняет воронку целиком: закрытый тизер → потраченный тизер →
выдача доступа → отзыв доступа.

Существует он ради одной проверки, которую юнит-тесты дать не могут: **закрытые поля не должны покидать сервер**.
Тест смотрит в тела HTTP-ответов, а не только в разметку, и отдельно бьёт `POST /api/analyze` в обход интерфейса —
клиентское скрытие поверх полного ответа пейволлом не является. Если кто-то заменит белый список в
`src/signals/visibility.ts` на спред, упадёт именно этот тест.

Браузер берётся установленный в системе (`channel: 'chrome'` в `playwright.config.ts`), поэтому
`npx playwright install` не нужен. Если появится CI — убрать `channel` и добавить в пайплайн
`npx playwright install --with-deps chromium`.

Прогон мутирует состояние пользователя и поэтому начинается со сброса через служебный роут `/__control?reset=1`,
который живёт только в `e2e/server.ts`. В приложении таких роутов нет.

## Продакшн

Шага сборки нет: `npm start` запускает `tsx src/server.ts`, который срезает типы на лету. Это сделано намеренно —
хостинги обычно ставят только production-зависимости (`npm ci --omit=dev`), где нет ни `typescript`, ни `@types/*`,
поэтому компиляция на сервере невозможна. Проверка типов живёт в `npm run typecheck` (локально и в CI).

Требования к платформе: `npm ci --omit=dev` + `npm start`, ничего больше.

### Деплой на Bothost

Проект собран под ограничения платформы:

- **Точка входа** — определяется через `package.json` → `scripts.start`. В «Дополнительных настройках» поле можно
  оставить пустым.
- **Порт** — берётся из переменной `PORT`, которую платформа подставляет сама.
- **Адрес** — сервер слушает `0.0.0.0` (иначе платформа отдаёт 502).
- **Никакой сборки в `/app`** — платформа монтирует в `/app` исходники из git уже после сборки образа, поэтому
  любые артефакты, положенные туда на этапе build, затираются. Приложение запускается прямо из `src/` через `tsx`.
- **Кастомный Dockerfile не нужен** — галку «Use custom Dockerfile» включать не требуется. Лежащий в репозитории
  `Dockerfile` предназначен для других хостингов. Исключение — если нужен показ коммита в админке, см. ниже.
- **База данных** — внутренний PostgreSQL Bothost работает без TLS, поэтому `DATABASE_URL` указывается без
  `sslmode`. Отдельной переменной для SSL нет.
- **Ветка** — `main`.

```bash
docker build -t forex-signal-miniapp .
docker run --env-file .env -p 3000:3000 forex-signal-miniapp
```

### Какой коммит сейчас работает

Админка (`/admin.html`) показывает строку вида `v0.1.0 · 066398e (.git) · запущен 21.08, 17:30`, то же уходит в лог
при старте. Хеш ищется по порядку: переменная окружения (`COMMIT_SHA`, `GIT_COMMIT`, `GIT_SHA`, `APP_VERSION`) →
чтение `.git/HEAD` напрямую → `git rev-parse`. В скобках указан сработавший источник, так что видно, чему верить.

Чтение `.git` намеренно сделано без вызова `git`: в `node:20-slim` бинарника нет, а каталог `.git` прочитать можно.
Работает это только там, где каталог доезжает до контейнера.

**На Bothost он не доезжает.** Платформа кладёт в build-контекст исходники без git-метаданных, поэтому
`COPY .git ./.git` в `Dockerfile` валил сборку целиком (`COPY failed: stat .git: file does not exist`) — строка
удалена и возвращать её нельзя. Единственный рабочий путь на этой платформе: завести в панели переменную `GIT_SHA`
со значением хеша. Минус — обновлять её руками при каждом деплое.

Если приложение не может определить коммит, оно при старте пишет в лог список переменных окружения, в названии
которых есть `COMMIT`, `SHA`, `GIT` или `REVISION` — если платформа подставляет хеш под своим именем, его видно
там, и достаточно продублировать значение в `GIT_SHA`.
